# 订阅代理池与账号专用节点

在管理后台的 **代理管理** 页面管理。原有 HTTP、HTTPS、SOCKS 手工代理保持兼容。

## 多订阅

添加任意多个订阅，分别设置名称、链接、启用状态和刷新间隔。链接是敏感凭据，保存后不回显；编辑时留空表示保留原链接。保存设置后执行单订阅或全部刷新，查看后台任务状态和节点数量。刷新失败保留上一份可用配置，不把失败当成空订阅。

订阅格式由 mihomo 原生 provider 解析，不执行订阅中的规则、脚本或系统网络设置。各订阅有独立命名空间，同名节点不会跨订阅覆盖。

- 包含正则：仅保留名称匹配的节点；留空不过滤。
- 排除正则：例如 `香港|Hong Kong|中国|大陆|China`。这是**节点名称**筛选，不是实际出口地区检测。
- 去重正则：通过捕获组提取同组标识，例如 `^(日本\d+).*`。
- 优先正则：同组内优先保留匹配项，例如 `直连`。不按相同 IP 自动合并不同线路。

订阅节点出现在原代理表中，可检测、修改标签、启停及限制账号。其监听 URL 由内核管理，不可手工改写。刷新不会覆盖用户手工禁用状态；退订/过滤掉的节点停止监听并在代理表禁用，不静默解绑账号或回落直连。

## mihomo 托管

默认在需要订阅时查找可执行文件；可以指定本地二进制路径。当前托管进程与自动安装支持 Linux，其他平台仍可使用原有手工代理功能。未找到且允许自动安装时，从官方发布下载并验证摘要，随后运行 codex2api 专用实例。不自动接管其他 mihomo 进程，不改系统代理、TUN、系统 DNS 或防火墙。

控制接口和每节点监听均绑定回环地址，使用随机密钥/认证，不需要向公网开放新端口。内核运行状态和失败原因显示在页面。

持久化目录默认 `/data/proxy-subscriptions`，可通过 `PROXY_SUBSCRIPTION_DATA_DIR` 指定数据父目录，模块会在其下创建 `proxy-subscriptions` 子目录。目录保存订阅私密配置、原始订阅缓存、节点稳定端口映射及内核文件；务必将其置于持久化卷并限制访问，按凭据数据维护，不提交到 Git。容器重建后会从持久化配置恢复。

## 节点访问范围

**共享**为默认：节点可以参加公共代理池选择。

**仅指定账号可用**：设置一个或多个允许的账号。其他账号不能通过公共池、组代理、手工绑定或旧会话粘性绕过限制；没有可用出口时失败关闭，不回落到本机直连。公共自动均衡不使用专用节点。

访问白名单不等于自动绑定。需要固定出口时，还应使用原有的“绑定账号”功能将该账号绑定到节点。限制已有代理时，如存在白名单外的绑定账号，先解除或修正绑定，再保存限制。

不要用“禁用节点”代替“专用”：禁用是可用性开关，不是账号访问范围。订阅刷新应用新内核配置时会短暂重连；不会修改系统网络或重启 PostgreSQL/Redis。
